1. Executive Summary & Problem Formulation

Underground mining operations involve high-risk, GPS-denied environments subject to hazardous gas accumulations (explosive methane CH₄, toxic carbon monoxide CO, oxygen depletion), structural timber collapse, and rough rock talus. Conventional wheeled ground rovers are easily immobilized by blasted rock talus and rail debris, while conventional open-rotor quadcopters suffer catastrophic crashes upon contacting mine walls, roofs, or support timbering.

The MINE-X Solution: A unified digital-twin inspection system pairing an interactive 3D subterranean mine cavern with a Spherical Protective Cage Drone. The outer spherical cage ($R = 1.35\text{m}$) rolls along the mine floor and haulage rails for ground locomotion while an internal stabilized gimbal keeps the optical inspection camera, searchlights, and avionics strictly upright and level. In open stopes, the drone takes off into flight mode with spinning propellers and dynamic aerodynamic banking.

3. Spherical Drone Engineering Details

Subsystem Design Specification Physical Rationale / Benefit
Protective Outer Cage Geodesic icosahedron wireframe (Radius = 1.35m) with 5 carbon toroid rings and anodized orange node brackets. Open mesh allows 100% rotor airflow with zero prop-wash throttling. Protects rotors from rock walls, timber portals, and roof strikes.
Concealed Ground Drive Internal drive track ring near inner cage equator + concealed micro-actuator housing tucked flush beneath chassis. Eliminates large conspicuous external wheels that get snagged in tight mine fissures. Produces clean ground rolling locomotion.
Inner Gimbal Core Double-deck carbon-fiber chassis with top brass/gold dome antenna puck and decoupled rotational kinematics. Counter-rotates dynamically during ground rolling to keep the optical inspection camera, searchlights, and avionics strictly level.
Powertrain & Rotors 4 carbon arm spars, brushless motor stators, 2-blade carbon props, and semi-transparent blur discs. RPM dynamically scaled from telemetry packets (0-100%). Blur discs scale in opacity up to 0.75 during flight and drop to 0 on E-Stop.
Vision & Illumination Forward optical inspection camera + twin high-power searchlights casting Three.js SpotLights and volumetric conical beams. Penetrates unventilated dark mine corridors with 50-meter illumination range for visual inspection of rock faults.

4. Multi-Mode Kinematics Mathematical Model

The drone executes decoupled state-based kinematic updates at 60 FPS in Three.js:

1. GROUND ROLLING KINEMATICS (Altitude <= 1.42m and Delta Distance > 0.002m):
   local_forward = -(dz * cos(yaw) + dx * sin(yaw))
   roll_delta    = (local_forward / cage_radius) * 2.2
   cage_angle_x += roll_delta
   outerCageGroup.rotation.x = cage_angle_x

   // Horizon Gimbal Stabilization:
   innerCoreGroup.rotation.x = lerp(innerCoreGroup.rotation.x, 0.0, 0.25)
   innerCoreGroup.rotation.z = lerp(innerCoreGroup.rotation.z, 0.0, 0.25)

2. FLIGHT KINEMATICS (Airborne Altitude > 1.42m):
   outerCageGroup.rotation.x = lerp(outerCageGroup.rotation.x, 0.0, 0.08)
   innerCoreGroup.rotation.x = lerp(innerCoreGroup.rotation.x, target_pitch, 0.18)
   innerCoreGroup.rotation.z = lerp(innerCoreGroup.rotation.z, target_roll, 0.18)
   propeller_spin_speed     = max(0.35, motor_rpm_avg * 0.008)

3. EMERGENCY STOP (Armed == False):
   motors_rpm = 0.0
   propeller_blur_opacity = 0.0
   outerCageGroup.rotation.x = ceased
   innerCoreGroup.rotation.x = 0.0 (level settlement)

6. Control System Hardening & Telemetry Bug Resolution

During operator testing, an unresponsive control issue was reported where physical keyboard keys (WASD, RF, QE) and on-screen controls were not influencing drone movement. An autonomous deep diagnostic audit revealed the root cause and implemented a three-tier fault-tolerant resolution:

Root Cause Diagnosis: The server telemetry stream crashed on every client connection with TypeError: Object of type bool_ is not JSON serializable. In backend/simulator.py, cavern centerline distance interpolation returned NumPy arrays, causing self.ground_contact to become a numpy.bool_. Standard json.dumps() threw a fatal exception, immediately severing the WebSocket connection (active_clients: 0) and dropping all incoming control packets.
Component Vulnerability / Failure Mode Engineering Remediation
WebSocket Serializer FastAPI send_json rejected NumPy data types (np.bool_, np.float64). Engineered custom safe_dumps() serializer in websocket_manager.py converting NumPy types to native Python primitives.
Network Fail-Safe If WebSocket dropped or reconnected, commands were silently queued or lost. Implemented automatic HTTP REST fallback (POST /api/command) in dashboard.js so commands always execute.
Boot State Drone booted disarmed at rest; keyboard inputs on the ground were interpreted as rolling without visual climb. Drone boots ARMED and hovering at 4.5m in MANUAL flight mode with all action buttons enabled.
Position Recovery Drone traveling past terminal boundaries could become stuck against end-wall obstacles. Added RESET_POSITION / RESET command to immediately return the drone to Portal mouth ($X=0, Y=4.5, Z=25$).
